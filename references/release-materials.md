# 介绍、配图与模板

## 按读者的问题排列

首页首屏回答“是什么，能做什么”。下一个入口让读者看懂怎么获取、怎么开始。需要更详细的工作流时放到使用说明，实测证据放到案例区。单仓多 Skill 时，总库负责选择，单技能页负责安装和使用。单仓单软件时，首页可以同时承担介绍与下载。

- 中英文保留同一版版本、事实、功能边界与链接，分别校对阅读顺序和图中文字。
- 将可复制安装指令直接放在 README 的安装区，顶栏导航跳到这个区。详细安装页可以展开不同客户端的步骤和限制。自然语言提示词明确标为“复制到对话”，终端命令注明平台与 Shell。使用需要手动导入 ZIP 的客户端时，给出下载链接及实际界面操作。
- 首屏图优先显示实际产品或技能名称。已有可编辑源图时直接改必要信息并重新导出，不因文档换版重画无关图形。输出 GitHub 页面可用的图，并为宽图提供可读的手机版本和有意义的替代文本。
- Skill 可以用任务流程、分工、检查回路解释行为。软件优先从已运行的目标版本取真实界面截图，必要时遮盖敏感信息。设计草案标成示意，实测数据标明案例与适用范围。
- 用 GitHub 实际阅读宽度检查文字是否可读、图是否截断、图与图注是否一致。前后两个配图区解决同一个问题时合并内容或用链接衔接。

## 最新版更新摘要

每次准备 GitHub 新版时，在中文和英文首页各写一块当前版本摘要。位置紧跟首图，在安装入口之前。首页没有首图时，放在开头介绍之后、安装之前。摘要包含版本号、最重要的用户可见变化，以及“下载新版”和“完整更新说明”两个链接。

- Skill 链接对应的单技能 ZIP。软件有多个附件时，标明安装版、便携版或平台，再链接合适的附件。需要选择时链接该版本的附件区。
- 摘要只展示当前版。按版本保留原有 Release 和更新记录。预览阶段可以使用计划中的地址，但须标明尚未发布。正式交付核对两个链接与同一版本对应。
- 更新已有发布页时，去掉首页重复的旧摘要，保留现有导航和已确认内容。

可复用结构：

```markdown
> **最新版 · v[版本号]**
>
> [一两句话写用户能感知的变化]
>
> [下载新版](对应附件链接) · [完整更新说明](对应 Release 链接)
```

英文版同步使用 Latest version、Download the update、Full release notes。

## README 模板

按项目情况取用下列结构。保留现有项目入口和有效的导航锚点，避免用模板抹掉已确认内容。

| 区域 | 内容 |
| --- | --- |
| 标题与首图 | 产品或技能名，一句话用途，必要的流程图或界面图 |
| 最新版摘要 | 紧跟首图，写版本、关键变化、下载和完整更新说明 |
| 获取与安装 | 下载哪个文件，适用平台或客户端，直接可复制的指令 |
| 走一遍最小任务 | 一个可复现的输入、操作与预期结果 |
| 工作流程或功能 | 使用场景、主要步骤和返回的成果 |
| 已验证案例 | 环境、实测过程、结果证据与验证边界 |
| 版本及支持 | Release 链接、许可证、排查与反馈入口 |

## Release 说明模板

- 发布标题包含项目名和版本，说明本版用户能看到的具体改动。
- 附件列明用途、目标平台或客户端、安装或解压入口。
- 写清验证做了什么和结果，区分历史实测、本轮回归和未验收平台。
- 仅在用户需要时提供一份可发布的宣传摘要，保持图、页面、版本和附件相互对应。
