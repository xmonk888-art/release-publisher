# Skill 打包路线

## 选择发布单元

- 确认单技能目录与技能标识，保存 `SKILL.md`、实际引用的资源和脚本、必要的宿主配置、现有许可证。发布多技能仓库时为用户指定的技能独立分发。
- 同步面向读者的中英文 README、安装说明、必要案例和配图。将仓库内引用改写到 ZIP 内可访问的位置，仓库导航可指向实际线上地址。仅携带技能运行与介绍所需文件。
- 实际客户端的识别目录、调用语法和导入能力分别核对，必要时使用当前官方文档。现有安装要检查同名技能及自定义内容。使用 ZIP 导入的客户端提供可独立取得的附件。
- 在 Codex 上核对 `agents/openai.yaml` 的中文简短说明，保留已定义的标识、工具依赖、图标和调用策略。初次制作或更新 Skill 时可配合现有技能制作规范。

## 发布前验收

1. 核对目录名、frontmatter 的 name 和版本、公开调用名、许可证与 Release 标签。复用目标宿主的格式校验工具，明确结构检查和真实发现之间的差别。
2. 核对必要运行文件，确认所有相对引用与页内入口在独立目录内有效。ZIP 顶层采用技能目录，内部保留完整相对结构；排除本机历史记录、凭证、私有项目素材和发布工作区。
3. 解压到新目录，打开两种语言的介绍，核对桌面/手机变体和用到的图。必要时在隔离环境中加载技能并执行最小只读任务，记录目标客户端实际识别结果。
4. 版本发布后从公开附件链接下载同名 ZIP，核对哈希并解压回查。仓库网页更新与 ZIP 同步是两项独立检查；根据用户指定范围发布对应版本。

验收例子：旧包指向旧工作流图，当前仓库已经换为工作看板和实测图。打包时同步两个 README 的章节位置、图文件、相对引用、安装入口和版本说明。归档页上的旧版本仍可按原标签追溯。
