# 软件图文制作与验收

## 先核对版本和操作

- 运行本轮说明所指的版本，用可公开的样例走完一条核心流程。记录实际按钮名称、选项默认值、结果状态和输出位置。兼容范围、依赖、安装方式和实测数据各自以已有证据为准。
- 用隔离的测试输入和输出目录。截图和 GIF 只使用获准公开的样例，裁去或遮盖用户名、本机路径、客户文件和无关窗口。保留真实的操作结果，必要时注明数据来自样例。

## 软件使用流程图

- 从用户目标起笔，按“输入 → 关键选择 → 执行 → 查看结果”组织。优先讲默认路径。选择会改变输出位置、结果或下一步时才画分支，写清条件和去向。每个节点用实际界面文案和动作短句，让读者能照图操作。
- 用清楚的阅读方向和对齐的节点，避免交叉箭头及仅靠颜色区分状态。按 GitHub 正文宽度和窄屏检查字号、换行和裁切。保留可编辑源稿，再导出页面可用的图片。示意图标明是流程示意。

## 功能截图与试用 GIF

- 截图紧跟对应的功能说明，保留读者辨认入口和结果所需的上下文。图注说明何时使用、点哪里、会看到什么。为图片写有意义的替代文本，缩放后细节难读时提供原图链接。
- 用户要求演示，或动作顺序适合用动图说明时，做一个能独立看懂的短循环。用真实录屏或按实际操作顺序排列的真实截图展示一个任务，留足读取按钮和结果的时间。用截图制作时称为步骤演示。剪掉等待时可注明已省略，避免让播放时长被误读为处理耗时。
- 用浏览器检查 GIF 的实际播放、步骤停留和循环。控制文件大小，同时保留辨认关键操作所需的清晰度。正文保留简明操作步骤，方便在动图无法播放时使用。

## 图文详情页和交付

- 在 [介绍模板](release-materials.md) 基础上，先让读者看懂用途、适用平台和下载入口，再用流程图或 GIF 走一遍任务。功能区按“场景、操作、可见结果”展开，配对应截图。将输出位置、常见失败和恢复方法放在读者用到的地方，避免反复展示同一张图。中英文共用同一套事实，译文保留能在软件中找到的实际按钮名。
- 先把页面预览、GitHub Markdown、公开素材和可编辑源稿集中到项目工作目录。用桌面和窄屏检查阅读顺序、图文对应、图片可读性、GIF 循环以及下载链接和锚点。“先做、不用上传”时以本地审阅稿收尾。
- 仅获准更新详情页时，只提交指定文档和获准公开的素材，核对程序版本、标签、Release 和安装包仍与此前一致。按 [GitHub 验收](github-release.md) 打开公开页面查看截图和 GIF。如果只验证了公开图片可读取或 GIF 可解码，分别说明，浏览器中的播放效果仍待核验。
